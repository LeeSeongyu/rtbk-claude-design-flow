# 핵심 기능 정의 — RTBK 부가가치세 신고·환급 의뢰 플랫폼

> 출처: `00-inputs/service-diagram/service-diagram.md`(User Flow), `00-inputs/IA/IA_customer.md`(업체 측),
> `00-inputs/IA/IA_accounting.md`(회계사무소 측). 세 자료는 상호 일관되며, 사람이 작성한 md를 정본으로 함.
> PNG 원본은 교차검증용(별도 재전사 미수행). Step 2(디자인 시스템)·Step 3(화면 정의)의 입력.

## 서비스 개요

RTBK는 **업체**와 **회계사무소**를 연결해 **부가가치세 신고·환급을 의뢰**하는 **웹 전용** 플랫폼이다.
업체가 문서를 올려 의뢰하면, 지정 회계사무소가 공제/비공제를 검토하고 필요한 항목을 업체에 되물어(Note Taking)
확정한 뒤 신고서를 제출한다. 결제는 **에스크로**(업체 결제 예치 → 제출 완료 시 정산) 방식이다.

- **역할 2개**: 업체(대표/경리직원) · 회계사무소(회계사/기장직원)
- **GNB(상단 네비게이션 바)**: `부가가치세`와 `홈택스 연동`(업체 측)이 **같은 위계**의 상단 네비 항목
  + 향후 확장용 빈 슬롯 → 현재 범위는 `부가가치세`(+ 업체 `홈택스 연동`)
  - 회계 측 `부가가치세`는 하위 **탭 2개**: `의뢰 관리` · `신고서 작성`
- **알림**: 웹 내 알림 기능 (별도 앱/푸시 없음)
- **핵심 상호작용 루프**: 검토 요청 ↔ Note Taking 왕복(회계 A4 ⇄ 업체 C7 ⇄ 회계 A5), 완료 시 신고서 제출

전체 성공 경로: `업체 가입→문서 의뢰→에스크로 결제` → `회계 배정→검토→검토요청` → `업체 Note 회신` →
`회계 (추가검토 반복)→신고서 제출` → `완료 + 에스크로 정산`.

## 영역별 핵심 기능

### 영역 0. 인증 (공통 — 업체·회계사무소 동일)
- **기능: 회원가입 / 로그인**
  - 목적: 두 역할의 서비스 진입점
  - 세부: 이메일(ID)+비밀번호 로그인, **카카오/네이버 소셜 로그인**, 이메일 찾기, 비밀번호 찾기 → 성공 시 메인화면
  - 관련 화면 후보: 로그인/회원가입, 소셜 인증 플로우, 메인화면
  - 우선순위: **High**
  - 근거: IA_customer §메인탭1, IA_accounting §메인탭1(동일), service-diagram C1/A1

### 영역 1. 업체 측 — 문서 관리 & 의뢰 개시
- **기능: 홈택스 연동**
  - 목적: 부가세 신고서·세액공제 내역 등 원천 데이터 확보
  - 위치: **`부가가치세`와 같은 위계의 상단 네비게이션 항목**(업체 측) — 사용자 확정(2026-07-28)
  - 관련 화면 후보: 홈택스 연동 화면(네비 항목)
  - 우선순위: **High**
  - 근거: service-diagram C2, 사용자 확정(네비 위치)
- **기능: 문서 관리 (Dropbox형 문서함)**
  - 목적: 부가세 신고서·세액공제 내역 등 자료를 올리고 관리하며 의뢰를 개시
  - 세부: 문서 리스트(업로드/삭제/의뢰하기), 부가가치세 신고서, 세액공제 내역
  - 관련 화면 후보: 문서 관리 화면
  - 우선순위: **High**
  - 근거: IA_customer §문서 관리, service-diagram C2~C3
- **기능: 의뢰 결정 (예상액 확인 → 진행 분기)**
  - 목적: 예상 절감액·환급 부담금을 보고 의뢰 진행 여부 결정 (진행/미진행 분기점)
  - 세부: 예상 절감액·환급 확인, 의뢰 진행 여부 선택
  - 관련 화면 후보: **팝업** — 의뢰 결정 단계
  - 우선순위: **High**
  - 근거: IA_customer §의뢰 결정 단계(팝업), service-diagram C4(분기)
- **기능: 에스크로 예약금 결제**
  - 목적: 의뢰 확정 및 지정 회계사무소 배정 트리거
  - 세부: 예약금 안내사항, 결제 창
  - 관련 화면 후보: **팝업** — 의뢰 예약금 결제
  - 우선순위: **High**
  - 근거: IA_customer §의뢰 예약금 결재(팝업), service-diagram C5

### 영역 2. 업체 측 — 의뢰 관리 & Note Taking
- **기능: 의뢰 진행 상태 관리**
  - 목적: 진행 중 의뢰의 단계(검토/noting n차)를 추적
  - 세부: 의뢰 리스트, 프로그레스 바(검토/noting → n차), Note Taking 진입
  - 관련 화면 후보: 의뢰 관리 화면
  - 우선순위: **High**
  - 근거: IA_customer §의뢰 관리, service-diagram C6
- **기능: Note Taking (검토 요청 응답)**
  - 목적: 회계사무소의 항목별 검토 요청에 업체가 답변
  - 세부: 검토 요청 항목(팝업 1페이지=1항목), Input box, 임시저장/저장
  - 관련 화면 후보: **팝업** — Note Taking
  - 우선순위: **High**
  - 근거: IA_customer §Note Taking(팝업), service-diagram C7
- **기능: 회신 / 소통**
  - 목적: Note 내용 회신, 필요 시 업체↔회계 소통
  - 세부: 회신하기, **〔강조·핑크〕 소통 수단 = 메일 보내기 · 카카오톡하기** (영상/전화 아님 — 사용자 확정 2026-07-28)
  - 관련 화면 후보: **팝업** — 회신
  - 우선순위: **High**
  - 근거: IA_customer §회신(팝업), 사용자 확정

### 영역 3. 회계사무소 측 — 의뢰 관리
- **기능: 의뢰 업체 리스트 관리**
  - 목적: 배정된 의뢰를 확인하고 검토/소통을 개시
  - 세부: 업체명·날짜·연락처, 부가세 신고서(첨부), 카드내역서(첨부), 상태·필터·정렬
  - 액션: 검토하기(팝업), Note Taking 확인(팝업), 업체 연락하기
  - 관련 화면 후보: 의뢰 관리 화면
  - 우선순위: **High**
  - 근거: IA_accounting §의뢰 관리, service-diagram A2

### 영역 4. 회계사무소 측 — 검토 (공제/비공제)
- **기능: 검토 (1차 AI + 2차 회계사)**
  - 목적: 항목별 공제/비공제를 판정하고 불분명 지출을 업체에 검토 요청
  - 세부(1차 AI): **AI가 부가세 신고서의 매입 신고내역 금액을 초과하는 금액의 항목을 카드내역서
    리스트에서 하이라이팅해 시각화**(엑셀 셀에 색 입힌 것처럼) — 사용자 확정(2026-07-28);
    항목별 공제·비공제 토글, 분류 설명, 수정/완료
  - 세부(2차 회계사): 카드내역 리스트, 공제·비공제 토글, 카드 소유주별 확인, 불분명 지출 표시·선택, 업체 연락, 검토 요청
  - 관련 화면 후보: **팝업** — 검토
  - 우선순위: **High**
  - 근거: IA_accounting §검토(팝업), service-diagram A3~A4
- **기능: Note Taking 확인**
  - 목적: 업체가 회신한 Note를 확인하고 추가 검토 필요 여부 판단
  - 세부: 카드내역 리스트 + Note 내용, 항목별 토글·설명, 불분명 지출 표시, 업체 연락, 완료/검토 요청
  - 관련 화면 후보: **팝업** — Note Taking 확인
  - 우선순위: **High**
  - 근거: IA_accounting §Note Taking 확인(팝업), service-diagram A5

### 영역 5. 회계사무소 측 — 신고서 작성·제출
> 회계 웹 `부가가치세`의 하위 탭 2개 중 하나. (`의뢰 관리`=영역3, `신고서 작성`=여기)
- **기능: 신고서 작성 (현재 Empty Case)**
  - 목적: 검토 완료 의뢰의 신고서 생성·제출 (제출 시 에스크로 정산)
  - **현재 범위: `신고서 작성` 탭 클릭 시 화면은 Empty Case(빈 화면)로 둔다 — 사용자 확정(2026-07-28).**
  - 원안(후속): 검토 완료 의뢰 리스트, 제출하기, 문서 생성하기(핑크), 신고 제출서 리스트
  - 관련 화면 후보: 신고서 작성 화면(= **Empty State**)
  - 우선순위: **Low** (이번 범위는 Empty만, 실기능은 후속)
  - 근거: IA_accounting §신고서 작성, service-diagram A6, 사용자 확정

### 영역 6. 크로스-역할 — 매칭·알림·에스크로 (확정 규칙)
- **매칭**: 업체 결제·의뢰 확정 시 **지정 회계사무소로 배정** (공개 풀 아님) — `C5 ⇒ A2`
- **검토 요청 알림**: `A4 ⇢ C7` — **웹 내 알림**으로 업체에 전달
- **Note 왕복(반복)**: `C7 ⇒ A5` → 추가 검토 필요 시 `A5 → A4` 반복 → 완료 시 `A6`
- **에스크로 정산**: 업체 C5 결제 예치 → 회계 A6 제출 완료 시점에 정산
- 우선순위: **High** (전체 플로우의 뼈대)
- 근거: service-diagram §핸드오프/규칙(확정)
- **의뢰 상태 전환 체계** (Step 2·3의 프로그레스 바, 필터, 정렬 기준) — 사용자 확정(2026-07-28)

  | 순서 | 상태 라벨 | 주체 | 설명 | 트리거 |
  |---|---|---|---|---|
  | 1 | 검토중 | 회계 | 배정 즉시 공제/비공제 검토 진행 (신규 유입은 '새 의뢰' 칩 표시) | C5 결제 확정 → A2 즉시 배정 |
  | 2 | 검토요청 | 회계→업체 | 불분명 항목에 대해 업체에 Note 요청 | A4 검토요청 버튼 |
  | 3 | 회신대기 | 업체 | 업체가 Note 작성 중이거나 아직 미회신 | A4→C7 알림 발송 시 |
  | 4 | 추가검토 | 회계 | 업체 Note 회신 수신, 회계사 재검토 중 | C7→A5 회신 도착 시 |
  | 5 | 검토완료 | 회계 | 모든 항목 공제/비공제 확정, 신고서 작성 가능 | A5 완료 버튼 |
  | 6 | 제출완료 | 회계 | 신고서 제출 완료 | A6 제출 시 |
  | 7 | 정산완료 | 시스템 | 에스크로 정산 처리 완료 | A6 제출 후 자동 |

    - **반복 루프**: `2 검토요청 → 3 회신대기 → 4 추가검토 → (더 필요하면) 2 검토요청`으로 순환 (Note 왕복 n차)
    - **'새 의뢰' 표시**: 의뢰접수(배정 직후)는 별도 상태가 아니라 **검토중 상태 + 리스트 아이템 앞 '새 의뢰' 칩**으로 표시 (4번 통일)
    - **업체 프로그레스 바 (업체 관점)**: `검토중 → 회신대기 → 검토완료 → 제출완료 → 정산완료`
      - 회계 내부의 검토요청·추가검토는 업체 관점에선 검토중/회신대기로 수렴
      - 회신대기에서 업체가 회신 → 반복 시 회신대기로 재진입
    - **회계 필터 기준**: 검토중 / 검토요청 / **회신대기** / 추가검토 / 검토완료 / 제출완료
      - '새 의뢰'는 필터가 아니라 리스트 아이템 앞 **칩**으로 강조
    - 근거: service-diagram C5→A2→A4→C7→A5→A6 흐름에서 도출, 사용자 확정.

## 확정 로그 (2026-07-28, 사용자)

- **실시간 소통 → 메일 보내기 · 카카오톡하기**로 확정 (영상통화·전화 아님). → 영역 2 회신
- **신고서 작성 탭 → Empty Case(빈 화면)**로 둠. 실기능은 후속. → 영역 5
- **1차 AI 검토 → 카드내역서 하이라이팅 시각화**: 부가세 신고서 매입 신고내역 금액을 초과하는
  금액의 항목을 카드내역 리스트에서 색으로 강조(엑셀 셀 색칠처럼). → 영역 4
- **홈택스 연동 위치 → `부가가치세`와 같은 위계의 상단 네비게이션 항목**. → 영역 1 / GNB
- **의뢰 상태 체계 7단계 확정** (검토중·검토요청·회신대기·추가검토·검토완료·제출완료·정산완료).
  의뢰접수는 검토중으로 통일, '새 의뢰'는 칩, 회신대기는 프로그레스바+필터, 업체 바는 업체 관점. → 영역 6

## 미해결 · 확인 필요 (잔여)

> 자료 간 불일치는 없었음. 아래는 정보 부족으로 사람 확정이 남은 항목.
