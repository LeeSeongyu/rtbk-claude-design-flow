# visual-verdict

생성된 화면 스크린샷을 레퍼런스 이미지와 비교해 **구조·패턴 일치도**를 채점하고,
결과를 **JSON**으로 반환하는 스킬입니다.

## 채점 철학 (중요)

- **픽셀 단위 복제(pixel-perfect)를 보는 것이 아니다.**
- **구조·패턴 일치도**를 본다: 레이아웃 계층, 컴포넌트 구성, 정보 위계,
  간격/정렬 패턴, 인터랙션 요소 배치, 디자인 토큰 일관성.
- 색상/여백의 미세한 오차는 감점 요인이 아니며, **구조적 불일치**가 핵심 감점 요인이다.

## 입력

- `generated` — 생성된 화면 스크린샷 경로
- `reference` — 비교 대상 레퍼런스 이미지 경로
- (선택) `context` — 케이스의 Task Flow / 핵심 기능 설명

## 채점 기준 (score, 0–100)

| 축 | 설명 | 비중 |
| --- | --- | --- |
| 레이아웃 구조 | 영역 분할·계층·그리드 일치 | 높음 |
| 컴포넌트 구성 | 버튼/입력/카드 등 구성요소 존재·배치 | 높음 |
| 정보 위계 | 제목·본문·강조의 우선순위 | 중간 |
| 패턴/토큰 일관성 | 간격·타이포·색상 토큰의 일관성 | 중간 |
| 인터랙션 요소 | 주요 액션의 배치·명확성 | 중간 |

## 통과 기준

- **score ≥ 85 → `pass`**
- **score < 85 → `fail`**

## 출력 형식 (JSON)

```json
{
  "score": 0,
  "verdict": "pass | fail",
  "differences": [
    "레퍼런스와 다른 구조적 차이점 목록"
  ],
  "suggestions": [
    "일치도를 높이기 위한 개선 제안"
  ],
  "reasoning": "점수와 판정에 대한 근거 설명 (구조·패턴 관점)"
}
```

### 필드 규칙

- `score` — 0~100 정수.
- `verdict` — `score >= 85`이면 `"pass"`, 아니면 `"fail"`.
- `differences` — 픽셀 오차가 아니라 **구조·패턴 차이** 중심으로 기술.
- `suggestions` — 구체적이고 실행 가능한 개선 항목.
- `reasoning` — 왜 이 점수인지 축별로 간결히 설명.

## 사용처

- `01-case-deriver`의 **Step 2 (결과 1차 채점)**에서 호출된다.
- 결과는 `data/02-design-preceeding/case-N/verdict.md`에 저장되고,
  `pass`면 `case-screens.md` 상태를 `검토중`으로 갱신한다.
